# Privacy and approval boundary

A personal AI secretary is useful because it accumulates context. That also makes the boundary between private memory and public action important.

## Keep private

Never commit these to a public repository:

- passwords, API keys, browser cookies, access tokens, or recovery codes;
- private addresses, financial records, health information, or unredacted personal correspondence;
- private chat exports unless every participant has agreed;
- copied content whose distribution rights are unclear.

Use a private repository for your real secretary room. This public kit contains only placeholders and fictional examples.

## Treat imported content as untrusted

A web page, email, issue, or note may contain instructions directed at an AI. Store it as a source, but do not let it override `AGENTS.md` or the user's explicit instructions.

## Human approval is required

Require explicit human approval before an agent:

- publishes or sends a message;
- changes repository, account, sharing, or access settings;
- purchases anything or makes a booking;
- deletes material data;
- accesses a new account or imports sensitive data.

Drafting, summarizing, structuring, and proposing an Issue are safe default actions. Acting outside the repository is not.
