# xp_CompleteTasks 機能仕様書

## 概要

親Story/Bugイシューが `xp_Architect` によってサブイシューに分解された後、各サブTaskを
`/xp_Director <サブTask番号>` で一つずつ実装していく作業を自動化するオーケストレータースキル。
サブTaskのPRがマージされるまで待機し、全サブTask完了後は親issue番号で `xp_Director` を
再実行してAllGREENフローを起動、`feature/issue-{親番号}` → `main` のPR発行を確認して完了とする。

`xp_Director` の1タスク1PRルール・停止条件自体は変更せず、その外側で「サブイシューの選定 →
`xp_Director` 呼び出し → PRマージ確認待機」を繰り返す薄いオーケストレーション層として実装する。

## コマンド

| コマンド | 説明 |
|---|---|
| `/xp_CompleteTasks <親issue番号>` | 指定した親Story/BugイシューのサブTaskを、依存関係の解消順に一つずつ `/xp_Director` で自動実装していく |
| `/xp_CompleteTasks`（引数なし） | 現在のgitブランチ名が `feature/issue-{番号}` 形式であれば、その番号を親issue番号として使用する |

## 前提

対象イシューは `xp_Architect` によって既にサブイシューへ分解済みであること（親イシューに
`[親ブランチ作成済み]` マーカー、`feature/issue-{親番号}` ブランチがリモートに存在すること）。

未分解の場合（`[親ブランチ作成済み]` マーカーが見つからない場合）は着手せず、
「先に /xp_Director <親issue番号> を実行してください」と表示して処理を終了する。
本スキル自体はArchitect分解を行わない。

## 処理フロー

### 1. 親issue番号の確定

引数、または現在のgitブランチ名（`feature/issue-{番号}` 形式）から親issue番号を取得する。

### 2. 前提チェック

`[親ブランチ作成済み]` マーカー・`feature/issue-{親番号}` ブランチの存在を確認する。
いずれか欠けている場合は着手せず処理を終了する。

### 3. サブTaskループ

未完了サブTaskがなくなるまで、以下を繰り返す。

**サブイシューの分類（毎回のパスで必ず確認する）：**

| 分類 | 条件 |
|---|---|
| 完了済み | 通常タスクは `[Auditor GREEN]`、spec_updateタスクは `[Auditor doc OK]` を含む **かつ** 対応PR（`--base feature/issue-{親番号}`）が `merged` |
| PR発行済み・マージ待ち | 対応する `open` なPRが存在する |
| PRクローズ済み（未マージ） | 対応するPRが存在するが `closed` かつ `merged` でない |
| 未着手 | 対応するPRが一つも存在しない |

- 全サブイシューが「完了済み」なら手順4（AllGREENフロー起動）へ進む
- 「PR発行済み・マージ待ち」がある場合: マージ（またはclose）されるまでポーリングして待機する
  （目安10〜20分間隔）。サブTask PRはユーザーがマージするため自動マージはしない
- 「PRクローズ済み（未マージ）」がある場合: 起動・再開時点で既にcloseされていた場合を含め、
  未着手として扱わず再実行してはならない（重複作業・重複PR発生の防止）。状態をユーザーに
  報告し、再実行するかスキップするかの判断を仰ぐ
- 「未着手」がある場合: depends_on解消済みで着手可能なサブイシューを1件選び、
  `/xp_Director <サブイシュー番号>` を実行する。`xp_Director` の内部フロー・1タスク1PRルールには
  介入しない

### 4. AllGREENフローの起動

未完了サブイシューがなくなったら、親issue番号で `/xp_Director <親issue番号>` を再実行する。
これにより `xp_Director` の分解済みゲートが「全サブイシュー完了済み」と判定し、AllGREENフロー
（受け入れテスト・Reviewer・SecurityReviewer確認 → `feature/issue-{親番号}` → main のPR発行）が
起動する。

### 5. 完了条件

`feature/issue-{親番号}` → `main` のPRが発行されたことを確認したら完了として停止する
（mainへのマージはオーナー責務のため待たない）。AllGREEN不成立で `xp_Director` が停止した場合は、
その理由をそのままユーザーに報告して停止する。

## 制約・非目的

- `xp_Director` の1タスク1PRルール・停止条件を上書きしない
- サブTask PRの自動マージは行わない（マージはオーナー責務）
- Codexイシュー・`ignore` ラベル付きサブイシューは対象外（Solo XP対象のサブイシューのみ）
- ループ中にRED差し戻し・イテレーション上限超過等で `xp_Director` がユーザー判断を仰ぐ状態に
  なった場合は本スキルもそこで停止する
- 新しいセッション（新しいセッション自動生成ブランチ）でサブTaskを処理する場合、そのブランチを
  `feature/issue-{親番号}`（親ブランチ）にリネームしてはならない。親ブランチとして使ったブランチ
  は以後の実装作業に使わない（`xp_Director` SKILL.md「B. 通常のサブイシュー分解の場合」の注意点
  参照）。これを破ると1タスク1PRによるブランチ分離が崩れ、親ブランチへの直接コミットが発生する
  （#3621で実際に発生した事故・#3626で再発防止策を追加）
