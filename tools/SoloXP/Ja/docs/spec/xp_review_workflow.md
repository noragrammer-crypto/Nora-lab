# xp_review_workflow 機能仕様

## 概要

xp_review_workflow はワークフローの振り返りと逸脱検知を担うスキル。
イシューログのコメントパターンを解析し、ワークフローの期待達成条件との差異を特定する。
改善案を1つだけ報告する。**ファイルを変更しない。報告のみで終了する。**

## コマンド

### `/xp_review_workflow`

XPスキルズワークフローを振り返り、
「ここがこう書かれていたら、もっとうまく動けたのに」
という箇所を**一個だけ**特定して報告する。

---

## 制約

- Noraの方針や判断とコンフリクトする提案はしない
- あくまで「Claude が働きやすくなる書き方の改善」にとどめる
- 指摘は**1つだけ**。複数列挙しない

---

## ワークフロー期待達成条件（正常完了条件）

各スキルの正常完了を示すコメントパターン（期待達成条件）：

| スキル | 期待達成条件 |
|---|---|
| xp_Architect | `[Architect完了]` またはサブイシュー発行コメント |
| xp_Tester | `[Tester完了]` |
| xp_Implementer | `[Implementer完了]` |
| xp_Auditor (test) | `[Auditor GREEN]` |
| xp_Auditor (doc) | `[PR発行済み #\d+]` |
| xp_Documenter | `[Documenter完了]` |

---

## 逸脱検知ロジック

以下のパターンで逸脱したIssue（逸脱Issue）を特定する：

- `[Tester完了]` の後に `[Implementer実行中]` がないイシュー
- `[Implementer完了]` の後に `[Auditor GREEN]` がないイシュー
- 同じフェーズが3回以上繰り返されているイシュー（差し戻しループ）
- `[Auditor GREEN]` なしに `[PR発行済み]` が記録されているイシュー

---

## 原因SKILL特定

逸脱が発見された場合、どのSKILL.mdが原因かを特定する（原因SKILL特定）。

1. 逸脱フェーズ（どのスキルのコメントの後で問題が起きたか）を特定
2. 担当スキルの SKILL.md を読む
3. 曖昧な指示・欠如している前提・矛盾する記述を探す

---

## 報告フォーマット

```
## ワークフロー振り返り

### 課題箇所
<スキル名>の「<セクション名>」

### 現状の書き方の問題
<具体的に何が起きたか / どう誤解されたか>

### 改善案（一言）
<どう書き直せばよいか>

### 根拠となったイシュー
- #<番号> <タイトル>（<理由>）
```

---

## 注意事項

- 指摘は事実ベースで。イシューログに記録がない推測は含めない
- 改善案はスキル定義の「書き方」の修正であること（実装変更・方針変更を提案しない）
- このスキルはファイルを変更しない。報告のみで終了する
