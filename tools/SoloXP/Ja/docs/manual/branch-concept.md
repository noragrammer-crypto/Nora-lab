# SoloXPはなぜブランチをこう使うのか（超入門）

Git・GitHubに詳しくなくても読める説明。コマンドはほぼ出てこない。

> Gitの操作方法そのもの（`merge`・`rebase`・`--base` 等）や、実際に詰まったときの対処は
> [ブランチ・PRマージ戦略についてのメモ](./branch-strategy.md) にまとめてある。あちらは
> 「一度Gitで事故ったことがある人」向けの資料なので、初めての人はまずこのページから読むこと。

## 3つの場所だけ覚える

SoloXPが使う場所は、たとえるなら3種類しかない。

| 例え | 正式名称 | 役割 |
|---|---|---|
| **完成品置き場** | `main`（デフォルトブランチ） | 動作確認済みの完成した状態だけを置く場所 |
| **大きな作業場** | 親ブランチ（`feature/issue-{番号}`） | 今回の大きな仕事（Story/Bug）をまるごと組み立てる場所 |
| **小さな作業机** | サブTaskのブランチ | 作業場の中の部品を1個だけ作るための、さらに小さい場所 |

```
小さな作業机
   ↓
小さな作業机 ─→ 大きな作業場
   ↓                 ↓
小さな作業机        完成
                     ↓
                    main
```

小さな作業机で部品（サブTask）を1つ作っては大きな作業場に運び込み、それを繰り返して
全部の部品が揃って検査（テスト・監査）に通ったら、初めて完成品置き場（`main`）に反映する。

> 上の図は「大きな仕事（`[Story]`・`[Bug]`）を複数の部品に分けて進めるとき」の形。
> 単発の小さな仕事（`[Task]`）の場合は大きな作業場を経由せず、小さな作業机から
> 直接完成品置き場（`main`）に反映することもある。

これがSoloXPの基本思想：

> **完成品置き場を直接いじらず、別の作業場で作って、検査が全部終わったら完成品側に反映する。**

いきなり `main` を直接書き換えないのは、「作りかけの状態」や「まだ検査していない状態」が
完成品置き場に混ざらないようにするため。

## でも、作業している間にも完成品側は動いている

ここが初心者がいちばん混乱しやすいところ。

大きな作業場（親ブランチ）を作ったのは1回きりの「その時点のコピー」。作業場の中で
部品を作っている間も、完成品置き場（`main`）の方は他の仕事（別のIssue）でどんどん
更新されていく。

**作業場を作った直後:**

```
main ─── A
          \
           作業場 ─ B ─ C ─ D
```

**しばらく作業した後（mainは先に進んでいる）:**

```
main ─── A ─ X ─ Y
          \
           作業場 ─ B ─ C ─ D
```

作業場の中では B・C・D という部品を組み立てているが、その間に完成品置き場では
X・Y という別の変更が加わっている。この「X・Yと、作業場の中身がぶつかっていないか
（同じ場所を別々に書き換えていないか）」は、最終的に完成品置き場へ反映するときに
確認される。

**ぶつかっていなければ、そのまま反映して終わり。ぶつかっていたら、X・Yを作業場へ
取り込んでからぶつかりを解消する必要がある。**

この「完成品置き場側の新しい変更を、作業場に取り込んでズレを解消する」操作に
`merge` や `rebase` という名前が付いている（ぶつかっていない場合は、この操作自体が
不要なことも多い）。

## 「ぶつかる」＝マージコンフリクト

X・YとB・C・Dが**同じ部分**を書き換えていた場合、どちらを採用すればいいか機械的には
決められない。この「ぶつかった状態」がいわゆる**マージコンフリクト**。

SoloXPを1人で使っていても、以下のようなときにこれが起きる：

- 大きな仕事を進めている途中で、優先度の高い別の作業に割り込んで先に `main` へ反映した
- 作業場の中で複数の部品（サブTask）を順番に作っている間に、時間が経って完成品置き場が
  先に進んでしまった

「1人で使っているのにコンフリクトが起きた」というのは異常事態ではなく、SoloXPの
運用上、普通に起きるもの。

## 詰まったらどうする？

ほとんどの場合、コーディングエージェント（Claude Code / Codex 等）が上記の取り込み・
衝突解消を自動でやってくれる。人間が毎回意識する必要はない。

ただ、エージェントが「コンフリクトが起きています」「作業場が完成品置き場より古いです」
のようなことを言い出したときに、上の図でいう「X・Yを作業場に取り込んでいる最中」なんだな、
とイメージできれば十分。

より詳しい仕組み（実際のブランチ名の付け方・コマンド・Claude Code Webでの挙動の違い等）は
[ブランチ・PRマージ戦略についてのメモ](./branch-strategy.md) を参照。
