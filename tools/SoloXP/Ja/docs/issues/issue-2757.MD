# #2757 [Bug] xp_issue2md/SKILL.md がHolyAutomater固有リポジトリをハードコードしており他リポジトリで誤動作する

## 本文

## 発見経緯
Nora-lab PR #21（SoloXP公開版レビュー成果の`git subtree push`）に対するCodex自動レビューで指摘。

## バグ内容
`SoloXP/skills/xp_issue2md/SKILL.md`（21行目付近）の `gh issue view` コマンドが `--repo noragrammer-crypto/HolyAutomater` を固定でハードコードしている。

```bash
gh issue view <issue_number> --repo noragrammer-crypto/HolyAutomater --json number,title,body,labels,state,createdAt,author,comments
```

> Codex指摘原文（Nora-lab PR #21 review comment, `tools/SoloXP/Ja/skills/xp_issue2md/SKILL.md:21`）:
> "When SoloXP is installed in any repository other than the author's private HolyAutomater repository, every `xp_issue2md` invocation queries the wrong repository. Users without access get an immediate failure, while users with access may archive an unrelated same-numbered issue; because `xp_Documenter` invokes this skill for every task, this blocks or corrupts the normal documentation workflow. Derive the current repository with `gh repo view` or omit the fixed `--repo` argument."

`xp_Documenter` が全タスクで本スキルを呼ぶため、他リポジトリでSoloXPを動かすと毎回誤ったリポジトリを参照する（アクセス不可なら即失敗、アクセス可能なら無関係な同番号イシューを誤操作する恐れ）。

## 修正方針（案）
- `--repo` を固定値でハードコードせず、`gh repo view --json nameWithOwner` 等で実行時のリポジトリを解決する
- または `--repo` 引数自体を省略し、`gh` のカレントディレクトリからの自動解決に委ねる
- HolyAutomaterでの動作は現状維持しつつ、他プロジェクトでも動く形に一般化する

`SoloXP/skills/xp_issue2md/SKILL.md`（本番運用中の実行スキル。編集時は要注意）
