# #3214 [Task] xp_Director/xp_Architect: GitHubアクセス方法表の環境マッピング修正＋MCPフォールバック追記

## 本文

## 概要

`#3205` の調査（`docs/gh-cli-dependency-audit.md` 参照）で判明した2点を修正する。

1. **既存バグ**: `SoloXP/skills/xp_Director/SKILL.md`「## GitHub アクセス方法」表が実態と逆になっている。
   現状「Claude Code Web → `gh` コマンド」「claude.ai / その他 → MCP経由」と記載されているが、
   実際には ClaudeCodeWeb は `gh` CLI が使えない（GraphQL/REST共に「このセッションでは有効化されていない」エラーで失敗する。#3204実環境再現済み）側であり、逆である。
2. `SoloXP/skills/xp_Director/SKILL.md`・`SoloXP/skills/xp_Architect/SKILL.md` 内の以下の `gh` コマンドに、
   `xp_issue2md`（#3204）で確立したパターン（gh優先→失敗時MCPフォールバック→フィールド正規化）を適用する：
   - `gh pr list --search ... --state merged`（AllGREEN前提条件のPRマージ確認）→ `mcp__github__search_pull_requests` 等
   - `gh issue close` → `mcp__github__issue_write`（method: update, state: closed）
   - `gh pr create --base main` → `mcp__github__create_pull_request`
   - `gh api .../sub_issues`（POST） → `mcp__github__sub_issue_write`
   - `gh label create` → **MCP側に直接対応するツールが見当たらない既知のギャップ**。本タスクで代替手段を設計する（例: 使用頻度の高いラベルを事前作成しておき「存在しなければエラーで停止しユーザーに手動作成を依頼する」フォールバックにする等）
