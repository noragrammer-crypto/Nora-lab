# #1733 [Enhancement] spec_update タスクでも xp_issue2md を呼び出す

## 本文

## 背景

`xp_Director` の spec_update タスクフローは `xp_doc_spec` → `xp_Auditor doc` → PR発行 となっており、`xp_Documenter`（および `xp_issue2md`）が呼ばれない。

そのため `/docs/issues/issue-<番号>.MD` が生成されず、`xp_Auditor doc` の issue2md チェックで欠落として検出される。

## 問題

spec_update タスクのイシューコメント履歴が `docs/issues/` に記録されず、後から追跡できない。

## 対応案

`xp_Director` の spec_update フローに `xp_issue2md <task_issue番号>` の呼び出しを追加する。

**変更対象フロー（xp_Director SKILL.md）:**

```
【spec_update タスクの場合】
i.   イシューの本文から親ストーリー番号を取得する
ii.  xp_doc_spec <親ストーリーイシュー番号>
ii-b. xp_issue2md <task_issue番号>  ← 追加
iii. xp_Auditor doc <task_issue番号>
     - OK → PR発行
→ 停止
```

または `xp_doc_spec` 内で `xp_issue2md` を呼ぶ設計でもよい。

## 完了条件

- spec_update タスク実行後に `/docs/issues/issue-<番号>.MD` が生成されること
- `xp_Auditor doc` の issue2md チェックが OK になること
