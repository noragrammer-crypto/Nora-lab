# #2971 [Task] Epic完了時にIssue Markdownをfinalizeしclosed状態へ同期する

## 本文

## 概要

`<epic>/docs/issues/issue-*.MD` に保存しているGitHub IssueのMarkdownスナップショットについて、取得時点では `state: open` だったIssueが、実際には後にclose済みになっていてもMarkdown側が更新されず、grep・検索時に古い状態が残る問題がある。

例: `modal/docs/issues/issue-1036.MD` は本文・コメントまで保存されている一方、front matter の `state` が取得時点のまま残る。

これを、SoloXPのEpic/Story完了タイミングで未確定Issueを再取得し、close済みIssueを最終スナップショットへ更新する仕組みに変更する。

## 方針

Issue Markdownは以下の2段階として扱う。

- **open中:** 作業用キャッシュ。多少のstaleは許容する
- **closed後:** 完成資料。Epic完了時にGitHubから再取得してfinalizeする

常時同期は行わず、SoloXPのAllGREEN〜main向けPR発行付近を同期ポイントとする。

## 処理フロー案

Epic/StoryのAllGREEN判定後、main向けPR発行の前後で以下を実施する。

1. 対象Epic配下の `docs/issues/issue-*.MD` を走査する
2. front matter が `state: open` のファイルだけを同期候補として抽出する
   - 例: `grep -rl '^state: open$' <epic>/docs/issues/`
3. 候補IssueをGitHub APIから再取得する
4. GitHub上で `closed` になっているIssueは、本文・コメント・front matterを含む最新版Markdownで置換する
5. まだ `open` のIssueは変更しない
6. 今回処理中の親Story/Bug自身はmain PR発行時点ではopenの場合があるため、Issue close後に最終取得してfinalizeする

## 責務分離

`xp_Director` は「コード・ドキュメントを書き換えず、判断と進行管理に徹する」という現在の責務を維持する。

そのため、同期処理そのものはDocumenter系の責務として独立させ、DirectorはAllGREEN時に以下のような処理を委譲する形を基本案とする。

```text
xp_Director
  ↓ AllGREEN
Issue archive finalize / Documenter
  ↓
xp_Auditor Story-level
  ↓
main PR
  ↓
親Story close後に親Issueを最終同期
```

実装上は既存のDocumenterに追加するか、Issue archive同期用の小さな処理/スキルとして分離してもよい。

## front matter案

最低限、既存の `state` を最新化する。

```yaml
state: closed
```

将来の差分判定用として、以下の追加も検討する。

```yaml
synced_at: 2026-08-17T00:00:00+09:00
github_updated_at: <GitHub issue updated_at>
```

ただし初期実装では複雑化を避け、**「state: open のローカルIssueをGitHubで再確認し、closedなら最新版で置換」**までを必須範囲とする。

`github_updated_at` による再取得スキップ等は将来拡張とする。

## 非目的

- Issueコメント追加のたびにMarkdownを同期する常時同期機構は作らない
- 全GitHub Issueを毎回APIで列挙し直さない
- Issue Markdownの `state` をSoloXPの依存解除・完了判定のSSOTにはしない
  - ワークフロー判定は引き続きGitHub上の状態や `[Auditor GREEN]` 等、既存ルールに従う
  - Markdown同期は検索・履歴・ローカル参照資料の鮮度改善を目的とする

## 期待する効果

- `grep` / ローカル検索で過去Issueを参照した際に、close済みIssueがopenとして残るstale情報を減らせる
- 全Issue常時同期を避けつつ、Epic完了という自然な境界で資料を確定できる
- ローカルIssueアーカイブを「作業中キャッシュ → 完了後の確定資料」として明確に扱える
- GitHub API呼び出しは `state: open` のローカル候補だけに限定できる

## 受け入れ条件

- [ ] AllGREEN〜Epic/Story完了フロー内にIssue Markdown finalize処理が組み込まれている
- [ ] 対象Epic配下で `state: open` のIssue Markdownだけが同期候補になる
- [ ] GitHub上でclosedのIssueは最新版Markdownへ更新され、front matterが `state: closed` になる
- [ ] GitHub上でopenのIssueは不要に書き換えられない
- [ ] 親Story/Bug自身もclose後に最終状態へ同期される
- [ ] 同期結果はSoloXPのdepends_on解除やAuditor GREEN判定には使用されない
- [ ] 常時同期・全Issue再取得を行わない
