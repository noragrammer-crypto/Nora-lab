# #2814 [Bug] xp_Auditor: Story-level GREEN判定がE2E結果のみを見ておりUnit/Functionalの失敗を無視する

## 本文

## 発見経緯

PR #2813（#2784対応）への Codex レビュー指摘（P1）より。

## 現状の設計

`SoloXP/skills/xp_Auditor/SKILL.md` の処理フロー：

1. **2節**「xp_RunTestSuites を実行する」: タスク/ストーリーいずれの場合も無条件に Unit + Functional テストを実行し結果を記録する
2. **3節**「E2E テストの判断・Story-level Auditor フェーズ」: ストーリーイシューの場合、E2E テストを実行し、
   - GREEN → `[Auditor GREEN]` を記録して xp_Director に返す
   - RED → バグイシュー起票、ストーリーは継続（クローズしない）

## 問題

3節の GREEN/RED 判定は **E2E の結果のみ** に基づいており、2節で実行した Unit/Functional テストの結果は
判定に組み込まれていない。そのため、Unit/Functional に失敗（既知・別スコープ含む）があっても E2E さえ
通れば `[Auditor GREEN]` が記録され、`xp_Director` がレビュー・PR発行・ストーリークローズに進んでしまう
可能性がある。

#2784（#2787）で追加した「既知・別タスクスコープのREDであっても、Story-levelでは例外なくストーリーを
クローズしない」という原則は、6節（別タスクスコープのバグ発見時＝E2E RED発生時のフロー）のスコープ限定
のみを対象としており、Unit/Functional の失敗がGREEN判定に反映されない今回指摘の構造的ギャップ自体は
解消していない（#2784 導入以前から存在する既存の設計ギャップ）。

## 対応方針（案）

- Story-level Auditor フェーズの GREEN 定義を「E2E・Unit・Functional すべてが GREEN であること」に修正する
- Unit/Functional に RED がある場合の処理（バグイシュー起票 or ストーリー継続）を明文化する

## 関連

- #2784, #2787（Story-level Auditorのスコープ限定を導入したPR）
- PR #2813 へのCodexレビュー指摘（P1バッジ）
