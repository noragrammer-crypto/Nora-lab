# #2818 [改善勧告] xp_Auditor所有権ベースブロック: バグの親ストーリーがクローズ済みの場合が未定義

## 本文

## 発見経緯

`#2807`（xp_Auditor: Story-level AllGREEN監査が別ストーリー由来の既知REDで相互ロックする）の xp_Reviewer レビュー中に発見。

## 内容

`#2807`/`#2809` で `SoloXP/skills/xp_Auditor/SKILL.md` の Story-level Auditor フェーズ（3節）に所有権ベースの非対称ブロックが導入された：

- バグの親が **自ストーリー** → ブロック（従来通り）
- バグの親が **他の「オープンな」ストーリー** → ブロックしない（重複検知コメントのみ）
- バグの親が **未設定** → 自ストーリーが所有権取得しブロック

この3分岐には「バグの親ストーリーが既に **クローズ済み**」というケースが含まれていない。文言を字面通り解釈すると「他ストーリー所有 → ブロックしない」に該当し得るが、そのバグを実際に直す主体（オープンなストーリー）はもう存在しない。結果として、誰にも所有されないまま `[Auditor GREEN]` が記録され続け、実在するリグレッションが恒久的に見逃される可能性がある。

## 再現条件（想定）

1. ストーリーA配下でバグイシューXが起票され、ストーリーAがクローズされる（Xが未クローズのまま残る、または再発する）
2. 別のストーリーBのStory-level E2EでXに対応するテストがREDになる
3. xp_AuditorがXの親（ストーリーA）を確認 → ストーリーAは既にクローズ済み
4. 現行の文言では「他ストーリー所有」に分類され、ストーリーBはブロックされず `[Auditor GREEN]` が記録される
5. Xは誰にも所有されず放置される

## 改善方針（提案）

3節の分岐に「親ストーリーがクローズ済みの場合」を追加する：
- 親が **クローズ済みのストーリー** → 未設定と同様に扱い、現ストーリーが所有権を再取得してブロックする（`replace_parent: true` で付け替え）

## 影響範囲

`SoloXP/skills/xp_Auditor/SKILL.md`（Story-level Auditor フェーズ・3節）、`SoloXP/docs/spec/xp_auditor.md`
