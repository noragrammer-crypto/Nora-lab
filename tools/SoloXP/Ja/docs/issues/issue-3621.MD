# #3621 [Task] xp_CompleteTasksスキルを新規作成する（サブTaskをxp_Directorで順次処理しAllGREENまで進めるループ）

## 本文

## 概要

親Story/Bugイシューが `xp_Architect` によってサブイシューに分解された後、各サブTaskを
`/xp_Director <サブTask番号>` で一つずつ実装していく作業は、現状ユーザーが都度手動で
次の番号を指定して実行する必要がある（`xp_Director` は1タスク1PRルールでPR発行のたびに
必ず停止する設計のため、意図的に自動継続しない。#1469）。

この「サブTaskを順番に流し込み、サブTaskPRのレビュー・マージ待ちが必要な場面ではきちんと
待機し、全サブTaskが完了したら親ブランチ→mainのPRが発行されるところまで進める」という
外側のループ制御を担う新規スキル `xp_CompleteTasks` を作成する。

## 提案するコマンド仕様

### `/xp_CompleteTasks <親issue番号>`

指定した親Story/Bugイシューについて、以下を自動的に繰り返す：

1. 親イシューのサブイシュー一覧を取得し、未完了（`[Auditor GREEN]`/`[Auditor doc OK]` かつ
   対応PRが `merged`）のサブTaskを特定する
2. depends_on解消済みで着手可能なサブTaskを1件選び、`/xp_Director <サブTask番号>` を実行する
3. サブTaskがPRを発行して停止したら、そのPRがマージされるまでポーリングして待機する
   （`xp_Director` の1タスク1PRルール・サブタスクPRの手動マージ運用はそのまま尊重し、
   本スキルはマージされるまできちんと待つ。マージ確認後に次のサブTaskへ進む）
4. 全サブTaskが完了したら、親issue番号で `/xp_Director <親issue番号>` を再実行し、
   `xp_Director` のAllGREENフロー（受け入れテスト・Reviewer・SecurityReviewer確認 →
   `feature/issue-{親番号}` → `main` のPR発行）を起動する
5. `feature/issue-{親番号}` → `main` のPRが発行されたことを確認したら完了として停止する
   （mainへのマージはオーナー責務のため待たない。CLAUDE.md「Issue/PRワークフロー」参照）

### `/xp_CompleteTasks`（引数なし）

現在チェックアウトしているブランチ名が `feature/issue-{番号}` 形式であればその番号を
親issue番号として使用する。パースできない場合はユーザーに確認する。

## 前提・スコープ外

- Architect未分解（`feature/issue-{親番号}` ブランチ未作成）の場合は対象外。先に
  `/xp_Director <親issue番号>` でサブイシューを発行してから使う運用とする
- `xp_Director` の1タスク1PRルール・停止条件・AllGREEN判定ロジック自体は変更しない。
  本スキルはあくまで「`/xp_Director` の逐次呼び出し + マージ待ちポーリング」の
  外側ループに徹する（`xp_Director` 自体への変更は不要）
- サブTaskPRの自動マージは行わない（CLAUDE.md「ブランチ運用」記載の手動マージ運用を維持）
- RED差し戻し・イテレーション上限超過・AllGREEN不成立等、`xp_Director` がユーザー判断を
  仰ぐ必要がある状態になった場合は、本スキルもそこで停止しユーザーに報告する
  （独自に強行しない）

## 見積もり

`.claude/skills/`・`dotfiles/.claude/skills/` へ自動同期されるため実体作成は正本のみ）
