# #3204 xp_issue2md が gh CLI 固定依存で ClaudeCodeWeb から実行不能になる

## 本文

## 背景

`SoloXP/skills/xp_issue2md/SKILL.md` の Issue 取得処理が `gh issue view` に固定されている。

```bash
gh issue view <issue_number> --json number,title,body,labels,state,createdAt,author,comments
```

最近の ClaudeCodeWeb 環境では `gh` CLI が利用できないケースがあり、GitHub へのアクセス手段自体は存在していても `xp_issue2md` が実行不能になる。

最新の weekly worklog（2026-08-15〜2026-08-22）でも、この理由で `xp_issue2md` を実行できず、対象 Issue のローカル MD 追従がスキップされている。

Haiku 以外のモデルでは別手段で取得して処理を継続する場合があるが、Skill 仕様としては `gh` 固定のため、モデルごとの挙動差・暗黙の回避に依存している状態。

## 問題点

- ClaudeCodeWeb で `gh` CLI が無いと Skill が停止する
- GitHub MCP / API 等の利用可能な取得手段があっても使えない
- モデルによって暗黙に回避できたりできなかったりし、再現性が低い
- worklog 集計や Issue MD 同期など下流処理に未処理が蓄積する
- Skill の本来の要件（Issue 本文・コメント・metadata の取得）より、実装手段（`gh` CLI）が強く固定されている

## 改善案

`xp_issue2md` の要件を「GitHub Issue の本文・コメント・metadata を取得して Markdown 化する」に寄せ、取得手段を固定しない。

候補:

1. `gh` CLI が利用可能なら従来通り使用
2. 利用不可なら GitHub MCP / API / コネクタ等の利用可能な手段へフォールバック
3. 取得結果を共通フォーマットに正規化して以降の処理を共通化
4. 取得手段の違いで出力 Markdown が変わらないことをテストする

## 受け入れ条件

- [ ] `gh` CLI が無い環境でも `xp_issue2md <issue_number>` が完走する
- [ ] Issue 本文・コメント全件・labels・state・createdAt・author を取得できる
- [ ] 既存の保存先判定と Markdown 形式を維持する
- [ ] `gh` 利用時とフォールバック利用時で同等の Markdown が生成される
- [ ] ClaudeCodeWeb 環境を想定したテストまたは E2E を追加する
