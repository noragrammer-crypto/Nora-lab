# #1691 [改善] feature/issue-* → main のPRにAllGREENマーカー確認のrequired status checkを追加する

## 本文

## 概要

#1690 で報告した「main へのPRがAllGREENゲートを経由せず直接発行・マージされる」問題（#1294実例）に対し、SKILL.md側の文言強化（#1690）に加えて、GitHub Actions による機械的なチェックを二段構えで導入する。

## 背景

`xp_Director` のAllGREENフローはプロンプト上の手順であり、エージェント（セッション）がこれを省略して直接 `gh pr create --base main` 相当の操作をしても止める仕組みがない。#1690 の対応（SKILL.md文言強化）はそれ自体では強制力を持たないため、CI側に軽量な機械チェックを併設したい。

## 提案

GitHub Actions で、`main` をbaseにしたPRに対する required status check を追加する：

- **発火条件**: PRのheadブランチ名が `feature/issue-*`（Solo XPの親ブランチ命名規則）にマッチする場合のみチェックを実行する
- **チェック内容**: PR本文または該当する親イシュー番号（ブランチ名から抽出）のコメント履歴を GitHub API で取得し、以下のマーカー文字列の存在を確認する
  - Story-level `[Auditor GREEN]`
  - xp_Reviewer のレポート（完了マーカー）
  - `[Auditor doc OK]`
- 揃っていなければ status check を fail させ、branch protection の required check 設定でマージをブロックする

Claude Code自体をActions上で動かす必要はなく、GitHub APIを叩くだけの軽量なNodeスクリプト1本で実装できる（#1294の事後検証時に行ったAPI呼び出しと同等のロジック）。

## 適用範囲（スコープ）

- 対象は **`feature/issue-*` ブランチからのPRのみ**。小説・Note記事等のコンテンツ保存（`claude/...` 等のブランチ名、または直接 `main` へのpush）は対象外とし、従来通り自由に行える
- コード系（Solo XP管理下のStory/Bug）の `main` 保護を厚くする一方、コンテンツ系の運用フローには影響を与えない設計とする
