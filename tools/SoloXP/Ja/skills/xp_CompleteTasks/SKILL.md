# XP CompleteTasks Skill

## コマンド

### `/xp_CompleteTasks <親issue番号>`

親Story/Bugイシューが `xp_Architect` によってサブイシューに分解された後、各サブTaskを
`/xp_Director <サブTask番号>` で一つずつ実装していく作業を自動化するオーケストレーター。
サブTaskのPRがマージされるまで待機し、全サブTask完了後は親issue番号で `xp_Director` を
再実行してAllGREENフローを起動、`feature/issue-{親番号}` → `main` のPR発行を確認して
完了とする。

### `/xp_CompleteTasks`（引数なし）

現在チェックアウトしているgitブランチ名が `feature/issue-{番号}` 形式であれば、その番号を
親issue番号として使用する。パースできない場合はユーザーに確認する。

---

## 前提

対象イシューは `xp_Architect` によって既にサブイシューへ分解済みであること
（親イシューに `[親ブランチ作成済み]` マーカー、`feature/issue-{親番号}` ブランチが
リモートに存在すること）。

未分解の場合（Architect未実行、`[親ブランチ作成済み]` マーカーが見つからない場合）は
着手せず、「先に /xp_Director <親issue番号> を実行してください」とユーザーに報告して
処理を終了する。本スキル自体はArchitect分解を行わない。

---

## 責務

- 親イシューのサブイシュー一覧の取得・未完了サブイシューの特定
- 次に着手可能な（depends_on解消済みの）サブTaskの選定
- `/xp_Director <サブTask番号>` の逐次呼び出し
- サブTask PRのマージ待ち（ポーリング）
- 全サブTask完了後、親イシューに対する `/xp_Director` 再実行によるAllGREENフロー起動
- `feature/issue-{親番号}` → `main` のPR発行確認をもって完了・停止

---

## 処理フロー

### 1. 親issue番号の確定

引数で指定された番号を使う。引数なしの場合は現在のgitブランチ名から `feature/issue-{番号}`
形式をパースし、番号を取得する（パースできない場合はユーザーに確認する）。

### 2. 前提チェック

親イシューの本文・コメントを取得し、`[親ブランチ作成済み]` マーカーの有無、
`feature/issue-{親番号}` ブランチの存在を確認する。マーカー・ブランチのいずれかが
欠けている場合（親イシューがArchitect未分解の場合）は着手せず処理を終了する。

### 3. サブTaskループ

未完了サブTaskがなくなるまで、以下を繰り返す：

1. `get_sub_issues` で親イシューのサブイシュー一覧を取得し、対応PRの状態（`merged` /
   `open` / `closed`（未マージ）/ PRなし）を **毎回のパスで必ず確認したうえで** 以下で分類する
   （スキルの起動・再開直後の1回目のパスも例外なく含む。ポーリング中に検知した場合のみ
   確認するのではなく、開始時点で既にPRがマージされずcloseされているケースも同じ扱いにする。
   Codexレビュー指摘・PR #3628）：
   - **完了済み**: 通常タスクは `[Auditor GREEN]`、spec_updateタスクは `[Auditor doc OK]` を
     含む **かつ** 対応PR（`--base feature/issue-{親番号}`）が `merged` 状態であること
     （`xp_Director` の「depends_on 解消判断」節と同じ確認手法・gh優先/MCPフォールバックを
     踏襲する。`[Auditor GREEN]` があるだけでは解消と見なさない）
   - **PR発行済み・マージ待ち**: 対応する `open` なPRが存在する
   - **PRクローズ済み（未マージ）**: 対応するPRが存在するが `closed` かつ `merged` でない
     （`merged` でも `open` でもない状態）
   - **未着手**: 対応するPRが一つも存在しない
2. 全サブイシューが「完了済み」なら手順4（AllGREENフロー起動）へ進む
3. 「PR発行済み・マージ待ち」のサブイシューが1件でもある場合：
   - そのPRがマージ（またはclose）されるまでポーリングして待機する（目安: 10〜20分間隔。
     `ScheduleWakeup`/`send_later` 等、セッションの自己待機手段が使える環境ではそれを使い、
     都度チャットで待たせない）。サブTask PRはユーザーがマージするため（自動マージしない）、
     マージされるまできちんと待つ。マージ待ちの間にレビュー指摘への対応が必要になった
     場合は、そのPR上で対応してから引き続き待機する
   - マージされたら手順1に戻る
   - ポーリング中にcloseされてマージされずに終わった場合は、次の3-bと同じ扱いに切り替える
3-b. 「PRクローズ済み（未マージ）」のサブイシューが1件でもある場合（起動・再開時点で既に
   closeされていた場合を含む）：
   - 未着手として扱い再実行してはならない（重複作業・重複PR発生の防止）
   - その状態をユーザーに報告し、再実行するかスキップするかの判断を仰いでから次へ進む
4. 未着手のサブイシューがある場合：
   - depends_on解消済み（依存先が完了済み。定義は上記1と同じ）で着手可能なサブイシューを
     番号の若い順に1件選ぶ
   - 選んだサブイシュー番号で `/xp_Director <サブイシュー番号>` を実行する。本スキルは
     `xp_Director` の内部フロー・1タスク1PRルールには介入せず、呼び出しと完了（PR発行 or
     停止理由の報告）を待つだけに徹する
   - 実行後、手順1に戻る

### 4. AllGREENフローの起動

未完了サブイシューがなくなったら、親issue番号で `/xp_Director <親issue番号>` を再実行する。
これにより `xp_Director` の分解済みゲートが「全サブイシュー完了済み」と判定し、AllGREENフロー
（受け入れテスト・Reviewer・SecurityReviewer確認 → `feature/issue-{親番号}` → main のPR発行）
が起動する。

### 5. 完了条件

`feature/issue-{親番号}` → `main` のPRが発行されたことを確認したら、本スキルは完了として
停止する（mainへのマージはオーナー責務のため待たない）。

AllGREENフロー内でAllGREEN不成立（受け入れテスト未GREEN・spec_update未完了・サブタスクPR
未マージ等）と判定され `xp_Director` が停止した場合は、その理由をそのままユーザーに報告して
停止する（本スキルが独自に強行しない）。

---

## 注意事項

- 本スキルは `xp_Director` の**1タスク1PR**ルール・停止条件を上書きしない。あくまで
  「`/xp_Director` の逐次呼び出し + マージ待ちポーリング」の外側ループに徹する
- サブTask PRの**自動マージは行わない**。マージはオーナー（ユーザー）が行う
- Codexイシュー・`ignore` ラベル付きサブイシューが混在するケースは対象外（Solo XP対象の
  サブイシューのみを扱う）
- ループ中にRED差し戻し・イテレーション上限超過等で `xp_Director` がユーザー判断を仰ぐ
  必要がある状態になった場合は、本スキルもそこで停止しユーザーに報告する
- 新しいセッション（新しいセッション自動生成ブランチ）でサブTaskを処理する場合、
  そのブランチを親ブランチ名にリネームしない（`xp_Director` SKILL.md「B. 通常のサブイシュー
  分解の場合」の注意点参照）
