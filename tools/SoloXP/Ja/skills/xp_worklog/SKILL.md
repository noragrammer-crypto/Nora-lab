# XP Worklog Skill

## コマンド

### `/xp_worklog <storycard_path または #issue番号>`

指定したストーリーイシュー（およびサブイシュー）の
作業時間コメントを集計してレポートし、`worklog/` に保存する。

### `/xp_worklog`（引数なし）

直近クローズされた Issue を全件集計して
イテレーションレポートを表示し、`worklog/` に保存する。

---

## 作業時間コメントのフォーマット

以下の形式のコメントを作業ログとして認識する：

```
作業開始 YYYY-MM-DD HH:MM JST
作業完了 YYYY-MM-DD HH:MM JST / 所要時間: XX分
tokens: prompt=XXXk completion=XXXk total=XXXk
model: <model-id>
作業中断 YYYY-MM-DD HH:MM JST
作業再開 YYYY-MM-DD HH:MM JST
```

- `作業開始` → `作業完了` で1セッションの所要時間を計算する
- 末尾に `JST` があるタイムスタンプはJSTとして扱う
- `JST` の記載がない過去のタイムスタンプはUTCとして解釈し、タイムゾーンを揃えてから所要時間を計算する
- `作業中断` / `作業再開` がある場合は中断時間を除外して計算する
- `所要時間: XX分` が明記されている場合はその値を優先する
- `tokens: prompt=XXXk completion=XXXk total=XXXk` は `作業完了` 行の直後に付記される（省略可）
- `model: <model-id>` は `tokens:` 行の次行に付記される（省略可）
- `tokens:` 行のフォーマットが崩れている場合はユーザーに確認する（自動補完しない）

### トークン消費の集計ルール

- `tokens:` 行から `prompt=XXXk`、`completion=XXXk`、`total=XXXk` の値をパースする
  - `k` サフィックスはキロトークン単位（例: `350k` → 350,000 tokens）
  - `k` サフィックスがない場合はそのまま整数として扱う
- 複数セッションにまたがるイシューはトークン消費を**合算**する
- `tokens:` 行が存在しないセッション・イシューは「記録なし」として表示する
  （「作業時間コメントが存在しないIssue」と同じ扱い）

### タイムスタンプが未記録の場合

初期のイシューで開始時間・終了時間が記録されていない場合:
- GitHub コメントのタイムスタンプ（`createdAt`、UTC）を参考に推定値を生成する
- 最初のコメントの `createdAt` を開始時間として使用する
- 最後のコメントの `createdAt` を終了時間として使用する
- 推定値は記録ファイル内で `(※推定)` と明記する
- フォーマットが崩れているコメントはユーザーに確認する（自動補完しない）

## 動作手順

### 引数ありの場合

#### 1. イシューを特定する

- ストーリーカードの `github_issue` または指定イシュー番号を取得
- ストーリーイシューのコメント一覧を取得する
- サブイシュー（タスクイシュー）も取得してコメントを収集する

#### 2. 集計・レポート出力

```
## ワークログレポート

ストーリー: #<番号> <タイトル>
期間: <最初のログ日付> 〜 <最後のログ日付>

### サマリー
合計時間: <n>h <m>分
見積もり: <total>pt（1pt ≈ 半日〜1日）

### イシュー別内訳

| イシュー | タイトル | 時間 | トークン消費 |
|---|---|---|---|
| #<番号> | <タイトル> | <n>h <m>分 | prompt=Xk completion=Xk total=Xk |
...
（`tokens:` 行がないイシューは「記録なし」と表示する）

### 作業ログ詳細

#### #<番号> <タイトル>
| 日時 | 所要時間 | 備考 |
|---|---|---|
| YYYY-MM-DD | <n>分 | <中断あり等> |
...
```

#### 3. worklog ディレクトリへの保存

集計結果を `worklog/YYYY/MM/<epic名>.md` に保存する。

**エピック名の判定:**
- イシューのラベルから `epic/<EpicName>` パターンを探す
- ラベルに含まれる日本語接尾辞（拡張・改善・修正等）は除去する
- リポジトリルートのディレクトリ名と前方一致で突合する
- エピックラベルがない場合は `misc` を使用する

**保存ファイルのフォーマット:**

```markdown
# <Epic名> — YYYY年MM月 作業記録

## サマリー
- 合計作業時間: Xh Ym
- 完了Issue数: N件（tokens記録あり: M件）
- 総トークン消費: Xk（Issue単位平均: Yk/issue）

## イシュー別記録

| Issue | タイトル | 開始時間 | 終了時間 | 作業時間 | トークン消費 | 備考 |
|-------|---------|---------|---------|---------|------------|------|
| #123  | タスク名 | YYYY-MM-DD HH:MM | YYYY-MM-DD HH:MM | XXm | prompt=Xk completion=Xk total=Xk | |
| #124  | タスク名 | YYYY-MM-DD HH:MM | YYYY-MM-DD HH:MM | XXm | 記録なし | (※推定) |
```

- 同じエピック・同じ月のファイルが既に存在する場合は、既存のイシュー行を保持しつつ新しいイシューを追加・更新する（マージ更新）
- 月をまたぐイシューは、各月のファイルにそれぞれ記録する

#### 4. issue2md の再実行

- `worklog/worklog_timestamp.md` から前回実行時の最終処理イシュー番号を読み取る
- 前回の最終番号から最新までのイシューに対して `xp_issue2md` を実行する
- issue2md の起動時間問題で最終的な内容にならないケースを再実行で更新する
- 処理完了後、`worklog_timestamp.md` に実行記録を追記する：

```markdown
| YYYY-MM-DD HH:MM | #<最終イシュー番号> | 処理件数: N件 |
```

#### 5. worklog_timestamp.md の更新

実行完了時に `worklog/worklog_timestamp.md` へ実行記録を追記する。

---

### 引数なしの場合（イテレーションレポート）

#### 1. 直近クローズ Issue を収集、オープン Issue をカウント

```bash
gh issue list --state closed --limit 20
gh issue list --state open --json number | python3 -c "import sys,json; print(len(json.load(sys.stdin)))"
```

直近の Sprint / イテレーション相当のクローズ済み Issue を対象とする。
期間の境界が不明な場合はユーザーに確認する。

#### 2. イテレーションレポートを出力

```
## イテレーションレポート

期間: <開始日> 〜 <終了日>
クローズ Issue 数: <n>件
残オープン Issue 数: <n>件

### 合計作業時間
<n>h <m>分

### Issue 別サマリー

| # | タイトル | 見積もり | 実績 | トークン消費 | 差異 |
|---|---|---|---|---|---|
| #<番号> | <タイトル> | <pt>pt | <n>h | prompt=Xk completion=Xk total=Xk | <±> |
...
（`tokens:` 行がないイシューは「記録なし」と表示する）

### 作業時間が記録されていない Issue
- #<番号> <タイトル>
...
```

#### 3. worklog ディレクトリへの保存

イテレーションレポートに含まれる全イシューを、エピック別・月別に `worklog/YYYY/MM/<epic名>.md` へ保存する。
（保存フォーマットは引数あり時と同一）

#### 4. issue2md の再実行・worklog_timestamp.md の更新

引数あり時と同一の処理を実行する。

## Epic単位トークン消費集計（ROI）

引数ありレポートおよびイテレーションレポートに、Epic単位のトークン消費ROI集計を追加する。

### 集計方法

1. `worklog/YYYY/MM/<epic名>.md` ファイルを走査し、対象Epicの全月データを収集する
2. 複数月にまたがるEpicは各月ファイルのトークン消費を合算する（同一Issue番号が重複する場合は最新月のエントリを優先する）
3. `tokens:` 記録がないIssueは平均算出から除外し「記録なし」として表示する

### 算出値と出力フォーマット

- **完了Issue数**: worklogファイルに記録されたIssue行数の合計（tokens記録あり・なし両方を含む）
- **総トークン消費**: `tokens:` 記録があるIssueの `total=Xk` 値の合算
- **Issue単位平均トークン消費**: 総トークン消費 ÷ `tokens:` 記録ありのIssue数

```
### Epic単位トークン消費ROIサマリー

| Epic | 完了Issue数 | 総トークン消費 | Issue単位平均トークン消費 |
|------|------------|--------------|-------------------------|
| SoloXP | 12件 | 2,400k | 200k/issue |
| DiscordAIbot | 5件 | 800k | 160k/issue |
```

（完了Issue数はtokens記録あり・なし両方を含む。平均はtokens記録ありのIssueのみで計算する）

---

## 注意事項

- 作業時間コメントが存在しない Issue はその旨を表示する
- フォーマットが崩れているコメントは自動補完せずユーザーに確認する
- 見積もりとの比較は参考値として表示する（責める目的では使わない）
- `worklog/` ディレクトリが存在しない場合は自動作成する
- 年・月ディレクトリも必要に応じて自動作成する
