# XP Reviewer Skill

## コマンド

### `xp_Reviewer <epic> <issue>`

現在のPR・ブランチのコードをレビューし、結果をイシューコメントとして記録する。
危険度ハイ（High Risk）な指摘は改善勧告イシューを自動起票する。

---

## 責務

- `code-reviewer` サブエージェント（feature-dev プラグイン提供）を呼び出してコードレビューを実行する
- レビュー結果をイシューコメントとして記録する
- 危険度ハイ（High Risk）な指摘については改善勧告イシューを自動起票する
- 中程度以下のリスク（Medium Risk / Low Risk）はコメントのみ（ユーザーアクション不要）

---

## 処理フロー

### 1. レビューの実行

**呼び出し方法（優先）:**

Agent tool で以下を渡して呼び出す：
- `subagent_type`: `code-reviewer`
- `prompt`: 現在のブランチの `git diff`（未コミットの変更がなければ、ベースブランチとの差分）をレビュー対象とする旨、
  CLAUDE.md記載の規約遵守も確認範囲に含める旨を明記する
- `isolation`: 指定しない（読み取り専用ツールのみで完結するため worktree 不要）

**出力のリスク分類へのマッピング:**

`code-reviewer` は confidence ≥ 80 の指摘のみを Critical / Important の2段階で返す。手順2のリスク分類には以下でマッピングする：

| code-reviewer 出力 | xp リスク分類 |
|---|---|
| Critical（バグ・セキュリティ） | 高リスク（High Risk） |
| Important（品質・規約違反） | 中程度（Medium Risk） |
| （confidence < 80 は元々報告されないため、低リスクは基本発生しない。指摘があれば低リスクとして扱う） | 低リスク（Low Risk） |

**`code-reviewer` が呼べない場合（ツール未対応・エラー）のフォールバック:**

**発動条件（いずれか1つでも該当したら発動）:**
- Agent tool の呼び出し自体がエラー・タイムアウトで失敗する
- `subagent_type: code-reviewer` が見つからない・利用不可というエラーが返る
- 呼び出しは成功したが、出力に指摘の有無・重大度が判断できる内容が一切含まれない（空応答・フォーマット崩壊）

**確認手順:**
1. 発生したエラーメッセージ、または不十分だった出力内容をそのまま記録する
2. 組み込みスキル `/review` を呼び出して同等のレビューを実行する：
   ```
   /review
   ```
3. `/review` の出力レポートを取得し、以降の手順（リスク分類・コメント記録）に進む

### 2. リスク分類

レビューレポートの各指摘をリスクレベルで分類する：

| リスクレベル | 対応 |
|---|---|
| 高リスク（High Risk） | イシューコメント記録 + 改善勧告イシューを自動起票 |
| 中程度（Medium Risk） | イシューコメントのみ（コメントだけ・ユーザーアクション不要） |
| 低リスク（Low Risk） | イシューコメントのみ（コメントだけ・ユーザーアクション不要） |

### 3. イシューコメントへの記録

レビュー結果を以下のフォーマットでイシューコメントとして記録する（書き込み）：

```markdown
## xp_Reviewer レポート

### 高リスク指摘（High Risk）
<高リスクの指摘一覧。なければ「なし」>

### 中程度・低リスク指摘
<中程度・低リスクの指摘一覧。なければ「なし」>

### 総評
<全体的な品質評価>
```

### 4. 高リスク指摘の改善勧告イシュー起票

高リスク（High Risk）な指摘が1件以上ある場合、各指摘に対して改善勧告イシューを発行（issue create）する：

```bash
gh issue create \
  --repo <owner>/<repo> \
  --title "[改善勧告] <指摘の概要>" \
  --body "<詳細な説明・改善方法・影響範囲>" \
  --label "bug"
```

起票したイシュー番号をレビューレポートのコメントに追記する。

---

## 注意事項

- Auditor の判断がクローズの場合は親イシューをクローズして構わない
- 中程度以下のリスクについてはユーザーからのアクションがない場合は現状維持
- コードファイルへの直接書き込みは行わない
