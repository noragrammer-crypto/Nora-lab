# XP Implementer Skill

## コマンド

### `/xp_Implementer <#issue番号>`

タスクイシューを読み込み、実装を行う。
単体テスト・機能テストのグリーンを目標とする。

> **呼び出し元**: xp_Director から呼ばれる。

---

## 責務

- テストを満たす実装を行う
- 実装後にテストを実行して結果を記録する
- 結果にかかわらず xp_Director に返す（Director が Auditor を呼ぶ）

**テストの正しさの判断は Auditor の責務。Implementer は判断しない。**

---

## 動作手順

### 0. 着手前チェック

#### ブランチ確認
- ClaudeCode Web の場合：タスク起動時に自動生成されたブランチを確認する
- ローカル / Codespaces の場合：作業用ブランチを作成する
  ```bash
  git checkout -b feature/issue-{番号}-{概要}
  ```
- **main ブランチのまま作業を開始しない**

#### 依存イシューの確認
- イシューの `depends_on` フィールドを確認する
- 依存イシューがある場合、**依存先サブイシューのコメントに `[Auditor GREEN]` があるかを確認する**
- `[Auditor GREEN]` がない場合は着手しない。イシューにコメントして終了する：
  ```
  ⚠️ 着手ブロック: Issue #XX の [Auditor GREEN] がまだ記録されていません。
  完了後に xp_Director から再度呼ばれます。
  ```

### 1. [Implementer実行中] マーカーを記録する

イシューにコメントを記録する:
```
[Implementer実行中]
```

### 2. タスクイシューを読み込む

- GitHub Issue の内容・コメントを取得する
- 以下を把握する：
  - 実装すべき機能・処理
  - 見積もり（pt・note）
  - 親ストーリーイシュー
  - 既存のテスト（UnitTest / FunctionalTest）
  - エピック名（`epic/<EpicName>` ラベルから取得）

### 3. 既存テストの確認

- `<EpicName>/__tests__/` の該当テストを読み込む
- テストが存在しない場合はその旨をイシューにコメントして xp_Director に報告する
- テストの期待動作を把握し、それを満たす実装を設計する

### 4. 実装

- 既存コードのスタイル・設計に合わせて実装する
- 過度な抽象化・将来対応は行わない（現タスクの範囲に留める）
- セキュリティ上の問題（インジェクション・XSS 等）が発生しないよう注意する

### 5. テスト実行

```bash
# 単体テスト
npm test -- --testPathPattern="unit"

# 機能テスト
npm test -- --testPathPattern="functional"
```

結果を記録する。GREEN でも RED でも次のステップへ進む。
**テストに疑念があっても自己判断で止まらない。Auditor に引き継ぐ。**

### 6. xp_Director に結果を報告して終了

```
## 実装完了

変更ファイル:
- `<path>`: <変更内容>

テスト結果:
- 単体テスト: PASS n件 / FAIL n件
- 機能テスト: PASS n件 / FAIL n件

<テストに疑念がある場合>
⚠️ 以下のテストについて Auditor に確認を依頼します:
- <テスト名>: <懸念内容>
```

---

## 注意事項

- テストのグリーンを目的に、テストを修正・削除してはならない
- テストに疑念があっても自己判断で止まらず、必ず xp_Director 経由で Auditor に引き継ぐ
- E2E テストは本スキルでは対象外（ストーリー完了時に確認）
