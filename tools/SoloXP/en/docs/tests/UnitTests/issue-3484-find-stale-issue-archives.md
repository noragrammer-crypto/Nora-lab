## Background

`<EpicName>/docs/issues/issue-*.MD` (Issue Markdown snapshot generated by `xp_issue2md`) is
Just save the state at the time of acquisition, and the front matter `state` will be automatically updated even if it is later closed on GitHub.
Not done (#2971). As a first step in the finalize process, select candidate issue numbers that require reconfirmation as `state: open`.
Created a new script `find-stale-issue-archives.sh` for definitive extraction (#3484). to GitHub API
Inquiries (actual closed determination/regeneration) are outside the responsibility of the script, and are handled by the skill side.
(LLM drive, gh/MCP fallback).

## Test case

1. The script file exists and is executable (with execution privileges)
2. Extract only the issue number of the file `state: open` (excluding `state: closed`)
3. `docs/issues` Returns empty if the directory does not exist (no error)
4. If there are no candidates (all `state: closed`), return empty
5. Ignore files other than `issue-*.MD` (`README.md`, etc.) even if they are mixed together.
6. Passing EpicDir with a trailing slash gives the same result (`SampleEpic` and `SampleEpic/` have the same result)
7. If EpicDir argument is omitted, display Usage and end with non-zero
