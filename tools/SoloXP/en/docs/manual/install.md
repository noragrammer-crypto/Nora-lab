# Installation manual

Steps to install the SoloXP skills (`skills/xp_*`, `skills/ProcessIssue`, and `skills/ProcessCodexIssue`) into your own repository / Claude Code environment.

> As a prerequisite, you need a working [Claude Code](https://claude.com/product/claude-code) setup (either the CLI or the Web version works).
> For preparing peripheral tools such as the `gh` CLI and Node/npm, see the [setup manual](./setup.md).

## 1. Bring SoloXP into your repository

Copy this directory (`SoloXP/`) to any location in your project.

```bash
# Example: place SoloXP/ at the root of your repository
cp -r /path/to/Nora-lab/tools/SoloXP/en <your-project>/SoloXP
```

As long as the `skills/`, `WORKFLOW.md`, and `CLAUDE.md.template` set stays together, the location itself doesn't matter (it will work as long as you complete the skill registration described below).

## 2. Register the skills with Claude Code

Claude Code recognizes skills in two scopes. Use either one, or both.

| Scope | Location | Effective range |
|---|---|---|
| Project scope | `<repository root>/.claude/skills/<skill name>/SKILL.md` | That repository only |
| Personal scope | `~/.claude/skills/<skill name>/SKILL.md` | All repositories in the execution environment |

Each directory under `SoloXP/skills/` (`xp_Director`, `xp_Architect`, `xp_Tester`, `ProcessIssue`, `ProcessCodexIssue`, etc.) corresponds one-to-one with a skill. Registration can be done either by "copying" or by "symbolic linking".

> `ProcessIssue` and `ProcessCodexIssue` play a different role than the `xp_*` skills. `xp_Director`
> (called with no argument) immediately delegates to `/ProcessIssue` — the actual issue selection and
> workflow-routing logic lives in `ProcessIssue` itself. `ProcessIssue`, in turn, delegates to
> `/ProcessCodexIssue` whenever it detects an issue generated by Codex's automated review. **If you
> register only the `xp_*` skills, the automatic-selection entry point (calling `xp_Director` with no
> argument) will not work.** Be sure to also register `ProcessIssue` and `ProcessCodexIssue` (see
> [ProcessIssue — Issue triage and automatic selection](./process-issue.md) for details).

### Copying (simple, environment-independent)

```bash
mkdir -p .claude/skills
for d in SoloXP/skills/xp_* SoloXP/skills/ProcessIssue SoloXP/skills/ProcessCodexIssue; do
  cp -r "$d" ".claude/skills/$(basename "$d")"
done
```

You will need to re-copy every time SoloXP is updated.

### Symbolic linking (updates on the SoloXP side are reflected automatically)

```bash
mkdir -p .claude/skills
for d in "$(pwd)"/SoloXP/skills/xp_* "$(pwd)"/SoloXP/skills/ProcessIssue "$(pwd)"/SoloXP/skills/ProcessCodexIssue; do
  ln -s "$d" ".claude/skills/$(basename "$d")"
done
```

If you reuse the same skills across multiple repositories, creating the same symbolic links under `~/.claude/skills/` lets any repository reference the same skill definitions (this project's own development environment uses this approach).

> Symbolic links cannot survive synchronization methods that carry files by walking history, such as
> `git subtree push` (what gets carried is the link string itself, not the file it points to, so the
> link breaks on the other side). If you are setting up a pipeline that continuously publishes and
> synchronizes a skill set to another repository, use a synchronization script that performs a real
> file copy instead.

## 3. Verify the installation

Start Claude Code and type `/` followed by `xp_Director`. If the skill candidates (command list) include the `xp_*` skill group along with `xp_Director`, registration succeeded.

> ⚠️ **Do not actually run it against a real issue number yet.** `xp_Director <issue number>` is not
> just a way to check that things are registered — it performs real work: commenting on the specified
> Issue, creating/pushing a branch, and issuing a PR. Running it against a real issue before you've
> finished `gh` CLI authentication and `CLAUDE.md` setup ([setup manual](./setup.md)) will make
> unintended changes. Limit this step to confirming that the skill shows up as a candidate; once setup
> is complete, follow the [usage tutorial](./tutorial.md) for the actual run.

Installation is now complete. Next, proceed to the setup manual.
