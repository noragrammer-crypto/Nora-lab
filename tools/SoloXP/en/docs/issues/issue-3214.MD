# #3214 [Task] xp_Director/xp_Architect: Correct environment mapping of GitHub access method table + Add MCP fallback

## Body

## Overview

Correct the two points found in the `#3205` investigation (see `docs/gh-cli-dependency-audit.md`).

1. **Existing bug**: `SoloXP/skills/xp_Director/SKILL.md` The "## GitHub access method" table is reversed from the actual situation.
   Currently, it is written as "Claude Code Web → `gh` command" and "claude.ai / Others → via MCP",
   In reality, ClaudeCodeWeb is on the side where `gh` CLI cannot be used (GraphQL/REST both fail with the error "Not enabled in this session". #3204 Actual environment has been reproduced), and it is the opposite.
2. In the following `gh` commands in `SoloXP/skills/xp_Director/SKILL.md` and `SoloXP/skills/xp_Architect/SKILL.md`,
   Apply the pattern established in `xp_issue2md` (#3204) (gh priority → MCP fallback on failure → field normalization):
   - `gh pr list --search ... --state merged` (PR merge confirmation for AllGREEN prerequisites) → `mcp__github__search_pull_requests` etc.
   - `gh issue close` → `mcp__github__issue_write` (method: update, state: closed)
   - `gh pr create --base main` → `mcp__github__create_pull_request`
   - `gh api .../sub_issues` (POST) → `mcp__github__sub_issue_write`
   - `gh label create` → **Known gap where no directly corresponding tool is found on the MCP side**. Design an alternative method in this task (e.g., create frequently used labels in advance and use a fallback to "stop with an error if it does not exist and ask the user to create it manually")
