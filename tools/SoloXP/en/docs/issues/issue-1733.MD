# #1733 [Enhancement] Call xp_issue2md also in spec_update task

## Body

## Background

The spec_update task flow of `xp_Director` is `xp_doc_spec` → `xp_Auditor doc` → PR issue, and `xp_Documenter` (and `xp_issue2md`) is not called.

Therefore, `/docs/issues/issue-<番号>.MD` is not generated and the issue2md check for `xp_Auditor doc` detects it as missing.

## Problem

The issue comment history of the spec_update task is not recorded in `docs/issues/` and cannot be tracked later.

## Countermeasure plan

Add a call to `xp_issue2md <task_issue番号>` to the spec_update flow of `xp_Director`.

**Flow to be changed (xp_Director SKILL.md):**

```
【spec_update タスクの場合】
i.   イシューの本文から親ストーリー番号を取得する
ii.  xp_doc_spec <親ストーリーイシュー番号>
ii-b. xp_issue2md <task_issue番号>  ← 追加
iii. xp_Auditor doc <task_issue番号>
     - OK → PR発行
→ 停止
```

Alternatively, the design may be to call `xp_issue2md` within `xp_doc_spec`.

## Completion conditions

- `/docs/issues/issue-<番号>.MD` is generated after running the spec_update task.
- `xp_Auditor doc` issue2md check is OK
