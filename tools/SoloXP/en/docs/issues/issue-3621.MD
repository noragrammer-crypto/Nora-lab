# #3621 [Task] Create a new xp_CompleteTasks skill (loop that sequentially processes sub-Tasks with xp_Director and progresses to AllGREEN)

## Body

## Overview

After the parent Story/Bug issue is decomposed into sub-issues by `xp_Architect`, each sub-Task is
Currently, users have to manually implement `/xp_Director <サブTask番号>` one by one each time.
It is necessary to specify the following number and execute it (`xp_Director` is a 1 task 1 PR rule, and it is executed every time a PR is issued.
Because it is designed to always stop, it does not intentionally continue automatically. #1469).

In situations where it is necessary to flow sub-tasks in order and wait for the review/merge of sub-TaskPR, this is done properly.
Wait, and when all sub-tasks are completed, proceed to the point where the parent branch → main PR is issued.''
Create a new skill `xp_CompleteTasks` that is responsible for outer loop control.

## Proposed command specification

### `/xp_CompleteTasks <親issue番号>`

Automatically repeat the following for the specified parent Story/Bug issue:

1. Obtain the list of sub-issues of the parent issue and check the incomplete (`[Auditor GREEN]`/`[Auditor doc OK]` and
   Identify the sub-task whose corresponding PR is `merged`)
2. Select one sub-task that can be started with depends_on resolved and execute `/xp_Director <サブTask番号>`
3. Once a sub-Task issues a PR and stops, poll and wait until the PR is merged.
   (The manual merge operation of `xp_Director`'s 1 task 1 PR rule/subtask PR will be respected as is,
   This skill will wait properly until it is merged. Proceed to the next sub-task after confirming the merge)
4. When all sub-tasks are completed, re-run `/xp_Director <親issue番号>` with the parent issue number,
   AllGREEN flow of `xp_Director` (acceptance test/Reviewer/SecurityReviewer confirmation →
   `feature/issue-{親番号}` → `main` PR issue)
5. After confirming that the PR for `feature/issue-{親番号}` → `main` has been issued, stop as completed.
   (Do not wait for merging to main as it is the owner's responsibility. See CLAUDE.md "Issue/PR Workflow")

### `/xp_CompleteTasks` (no argument)

If the currently checked out branch name is in the `feature/issue-{番号}` format, enter its number.
Use as parent issue number. If it cannot be parsed, ask the user.

## Assumptions/Out of scope

- Not applicable if Architect is not disassembled (`feature/issue-{親番号}` branch not created). first
  Use `/xp_Director <親issue番号>` to issue a sub-issue before using it.
- The `xp_Director` 1-task-1PR rule, stop conditions, and AllGREEN judgment logic itself will not be changed.
  This skill is only for "sequential calling of `/xp_Director` + polling for merge wait".
  Stick to the outer loop (no changes to `xp_Director` itself)
- Sub-TaskPR will not be automatically merged (manual merge operation described in CLAUDE.md "Branch operation" will be maintained)
- `xp_Director` will make decisions for users such as RED remand, iteration limit exceeded, AllGREEN failure, etc.
  If a situation arises where it is necessary to ask for help, this skill will also stop and report to the user.
  (Do not force it on your own)
