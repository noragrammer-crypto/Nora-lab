# #2814 [Bug] xp_Auditor: Story-level GREEN judgment only looks at E2E results and ignores Unit/Functional failures.

## Body

## How it was discovered

From Codex review pointed out (P1) for PR #2813 (corresponding to #2784).

## Current design

`SoloXP/skills/xp_Auditor/SKILL.md` processing flow:

1. **Section 2** "Run xp_RunTestSuites": Run Unit + Functional tests unconditionally and record the results for both tasks and stories.
2. **Section 3** “E2E Test Judgment/Story-level Auditor Phase”: For story issues, run E2E tests,
   - Record GREEN → `[Auditor GREEN]` and return it to xp_Director
   - RED → Bug issue filed, story continues (not closed)

## Problem

The GREEN/RED judgment in Section 3 is based on **E2E results only**, and the results of the Unit/Functional tests performed in Section 2 are
Not included in judgment. Therefore, even if there is a failure in Unit/Functional (including known/different scope), even E2E
If it passes, `[Auditor GREEN]` will be recorded and `xp_Director` will proceed to review/PR issue/story close.
There is a possibility.

Added in #2784 (#2787) "Even if the RED has a known/different task scope, the story will not be processed without exception at Story-level.
The principle of "not closing" is limited to the scope of Section 6 (flow when a bug is discovered in another task scope = E2E RED occurs)
The structural gap pointed out this time, in which Unit/Functional failure is not reflected in GREEN judgment, is itself
Not resolved (existing design gap that existed before the introduction of #2784).

## Response policy (draft)

- Correct the GREEN definition of the Story-level Auditor phase to "E2E, Unit, and Functional must all be GREEN"
- Clarify the process (file a bug issue or continue the story) when there is RED in Unit/Functional

## Related

- #2784, #2787 (PR introducing limited scope of Story-level Auditor)
- Codex review pointed out for PR #2813 (P1 badge)
