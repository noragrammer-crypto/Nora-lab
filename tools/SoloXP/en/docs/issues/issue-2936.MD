# #2936 [Task] pre-push.sh: symlink-disabled environment fallback + irrelevant staged change protection

## Body

## Overview

Correct two bugs in `.claude/hooks/pre-push.sh` (Complete reproduction test + correction implementation in a single task. CLAUDE.md TDD principle: Bug fixing is one task, one PR).

1. Whether or not a symlink can be created is determined only by determining `is_termux()`. In environments where symlink creation can fail even in non-Termux (e.g. Windows checkout without symlink privileges), there is no fallback, and if `ln -s` fails after `rm -rf`, the skill directory may be committed with lost status.
   - Added `can_create_symlinks()` (actual probe for `mktemp -d` + `ln -s`). Changed mode judgment to `is_termux || ! can_create_symlinks`.
   - Add a fallback to `cp -r` on failure for each `ln -s` call itself.
2. When committing `.claude/skills/` to correct drift, the unconditional `git commit` after `git add -A` is committed without a pathspec, including unrelated WIP changes that were already staged at the time of pre-push execution.
   - Before `git add` the synchronization target path, use `git diff --cached --name-only` to save the existing staged contents, and if it is non-empty, skip autocommit (the synchronized contents remain as git added).

The specific difference proposal has been described in the issue text (#2738) and has been locally verified.
