# #3486 [Task] Incorporating Epic cross-Issue Markdown finalize into daily-tasks

## Body

## Overview

The close of the parent Story/Bug issue itself (merging PR for main including `Closes #<番号>`) is an asynchronous event that occurs after the session of `xp_Director` ends, and cannot be detected only by the synchronous call (#3485) in the AllGREEN flow. Add a step to the existing cyclic execution mechanism `daily-tasks` skill that calls `xp_issueArchiveFinalize <EpicName>` across each Epic directory that has `docs/issues/`.

Enumerate target Epics by scanning the directory where `<dir>/docs/issues/` exists directly under the repository root (no need to maintain and manage a new Epic list). Since the API call is limited to only the `state: open` candidates for each Epic, it does not conflict with the non-purpose of "not always syncing all issues" in CLAUDE.md.

Enumerate each Epic directory with `docs/issues/` and call `xp_issueArchiveFinalize <EpicName>`

Design decisions:
- Incorporation into xp_Director (#3485) can only capture "the moment when the target Story has just completed", and the close of the parent Story/Bug itself (PR merge to main) cannot be detected because it is an asynchronous event after the session ends. This task was designed to pick up the missed items on a daily basis.
- Enumeration of target Epics is based on the existence of the `docs/issues` directory, eliminating the need for manual management of the Epic list.
- Commits resulting from finalize are added to the existing ``4. If there is a commit, issue a PR'' judgment, and new PR issuance paths are not increased.
- Specify that the number of scans and finalize items is not the SSOT of SoloXP's depend_on cancellation and Auditor GREEN judgment (non-purpose of #2971)
