# #3484 [Task] Issue Markdown finalize skill (xp_issueArchiveFinalize) new creation

## Body

## Overview

Create a new skill `xp_issueArchiveFinalize <EpicName>` that compares the file whose front matter is `state: open` among `<EpicName>/docs/issues/issue-*.MD` with the latest state on GitHub, and replaces it with the latest version of Markdown if it is already closed.

### Processing details

1. Identify candidate files with `grep -rl '^state: open$' <EpicName>/docs/issues/`
2. Get the issue number from the front matter `issue:` field of each candidate file
3. Perform a lightweight status check for each issue number: `gh issue view <n> --json state -q .state` (Fallback to `mcp__github__issue_read` method: `get` in case of failure)
4. If it is `closed` on GitHub, call the existing `xp_issue2md <n>` as is, and regenerate the entire body, comments, and front matter (including `state: closed`) (Do not create new Markdown generation logic. See existing implementation investigation comment in #2971)
5. If it's still `open` on GitHub, do nothing
6. After completion, report a summary of the number of scanned items, number of finalized items, and number of skipped items.
