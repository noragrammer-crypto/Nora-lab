# #2757 [Bug] xp_issue2md/SKILL.md hardcodes HolyAutomater specific repository and malfunctions with other repositories.

## Body

## How it was discovered
Pointed out in Codex automatic review of Nora-lab PR #21 (`git subtree push` of SoloXP public version review results).

## Bug details
The `gh issue view` command in `SoloXP/skills/xp_issue2md/SKILL.md` (around line 21) has a fixed hard-coded `--repo noragrammer-crypto/HolyAutomater`.

```bash
gh issue view <issue_number> --repo noragrammer-crypto/HolyAutomater --json number,title,body,labels,state,createdAt,author,comments
```

> Codex original text (Nora-lab PR #21 review comment, `tools/SoloXP/Ja/skills/xp_issue2md/SKILL.md:21`):
> "When SoloXP is installed in any repository other than the author's private HolyAutomater repository, every `xp_issue2md` invocation queries the wrong repository. Users without access get an immediate failure, while users with access may archive an unrelated same-numbered issue; because `xp_Documenter` invokes this skill for every task, this blocks or corrupts the normal documentation workflow. Derive the current repository with `gh repo view` or omit the fixed `--repo` argument."

Since `xp_Documenter` calls this skill for all tasks, if you run SoloXP in another repository, it will refer to the wrong repository every time (if it is inaccessible, it will fail immediately, and if it is accessible, there is a risk of accidentally operating an unrelated issue with the same number).

## Amendment policy (draft)
- Don't hard code `--repo` with a fixed value, resolve the repository at runtime using `gh repo view --json nameWithOwner` etc.
- Or omit the `--repo` argument itself and leave it to automatic resolution from the current directory of `gh`
- While maintaining the current operation in HolyAutomater, generalize it so that it works in other projects as well.

## Scope of influence
`SoloXP/skills/xp_issue2md/SKILL.md` (Execution skill during production operation. Be careful when editing)
