# Solo eXtreme Programming with AI Agents - Reference materials

## Overview of project concept
An individual developer builds a project management environment based on XP workflow that integrates GitHub, a flat file issue tracker, and a group of AI agents. Emphasizes visualization of time spans (weekly/monthly sprints) and operation in mobile environments (Android/Termux).

---

## Candidates for technical elements

### 1. Beans - flat file issue tracker

**Repository**: https://github.com/hmans/beans

**Features**:
- Single binary made by Go → Cross-platform compatible
- Save in Markdown format in `.beans/` directory
- Git manageable, read and write by both humans and AI
- Equipped with GraphQL query engine (token efficient)
- Built-in TUI (Terminal UI)
- Compatible with Claude Code official plugin

**Command example**:
```bash
beans init # initialize
beans prime # generate prompt for agent
beans graphql '{beans{id}}' # GraphQL query
beans tui # start TUI
```

**Android/Termux compatible**:
- Made by Go → ARM compatible binaries available (Please check: Termux can be built with `go install`)
- File-based → Git operations can be used as is
- Verification requirements: TUI rendering, GraphQL server startup

**Integrated approach**:
- Agent adds `beans prime` instructions to CLAUDE.md etc.
- Humans can use `beans tui` for an overview or directly edit Markdown in VS Code
- Synchronization with GitHub Issues: Bean → Issue generation with weekly script

### 2. XPPlanner interface candidates

**Features you're looking for**:
- Story card management
- Iteration planning (1-2 week sprints)
- Velocity tracking
- Timeline visualization

**Option A: Ready-made product**
- **Taiga**: Open source, agile focused, self-hostable
  - Problem: Web app = server operating costs, insufficient mobile optimization
- **Leantime**: Lightweight, made in PHP
  - Problem: Same as above, serious possibility for individuals
- **Linear/Height**: For startups
  - Issue: Overspec for individuals, privacy concerns

**Option B: Static site generation + GitHub Pages**
```
Beans data (.beans/*.md)
  ↓ Script (Python/GAS/Go)
Hugo template / Eleventy template
  ↓
HTML dashboard with timeline
  ↓ GitHub Pages
View on mobile browser
```
- Advantages: Serverless, Git integration, free customization
- Disadvantages: initial construction cost, low interactivity

**Option C: TUI extension**
- Extend `beans` TUI in Go and add timeline view
- Works directly with Termux
- Benefits: Highly integrated, mobile-friendly
- Disadvantages: Requires Go development skills, limited graphical expression

**Choice D: Obsidian Dataview plugin**
- Symlink Beans markdown to `Obsidian vault`
- Generate timeline with Dataview query
```dataview
TABLE status, priority, created
FROM ".beans"
WHERE type = "feature"
SORT created DESC
```
- Benefits: Utilizes Nora's existing workflow, supports mobile Obsidian
- Disadvantages: Depends on Obsidian, does not use GraphQL

### 3. GitHub × XP × Beans synchronization design

**XP element mapping**:
| XP Concepts | GitHub | Beans | Synchronization Timing |
|--------|--------|-------|----------------|
| Iteration | Milestone (Week1, Week2...) | bean metadata `iteration: week1` | Sunday Night Handoff |
| User story | Issue | bean (type: feature) | Manually created or automatically generated by AI |
| Task | Issue (child task) | bean (with parent_id) | Anytime |
| Completed story | Closed Issue | archived bean | Weekly close |
| Velocity | Milestone statistics | GraphQL aggregation | When generating weekly reports |

**Synchronization script proposal** (Python/GAS):
```python
# Run on Sunday night
def weekly_sync():
    # 1. Aggregate beans status for this week
    beans = run_graphql_query("{ beans(status: done) { id title } }")
    
    # 2. GitHub Milestone completed
    milestone = github.get_milestone("Week N")
    milestone.close()
    
    # 3. Milestone creation next week
    next_week = github.create_milestone("Week N+1", due_date="+7days")
    
    # 4. Migrate unfinished beans to next week
    for bean in beans_incomplete:
        github.create_issue(title=bean.title, milestone=next_week)
    
    # 5. Weekly report generation (Markdown)
    generate_report(beans, milestone)
```

**Cross-project aggregation**:
- Label usage: `project:novel`, `project:blog`, `project:tool`
- GraphQL: `beans(labels: ["project:novel"]) { ... }`
- Dashboard: Display the progress of each project in parallel

### 4. Agent conversation system

**Beans vs Gas Town vs Homebrew**

**Beans**:
- Specialized in task management, no conversation system
- Agent receives instructions via `beans prime`
- Conversation logs are managed separately (Slack/Discord/file)

**Gas Town** (https://github.com/steveyegge/gastown):
- Specialized in multi-agent coordination
- Communication between agents using Git worktree + mail system
- Terminology: rig (project), convoy (task bundle), bead (issue)
- Compatible with Claude Code/Codex
- Android compatible: Unknown (needs investigation)

**For homemade**:
- Optimized for Nora's "AI mercenary team" philosophy
- Draft composition:
```
agents/
  claude.md # Context for Claude
  gemini.md # Context for Gemini
  deepseek.md # Context for DeepSeek
shared/
  META.md # Overall project information
  TODO.md # Common task list
logs/
  2025-02-01-session.md # Conversation log
```
- Each agent reads `shared/` to synchronize state
- Logs are managed with Git and can be reviewed later

**Recommended configuration**: Beans (task management) + homemade log system (conversation history)
- Reason: Beans are lightweight and easy to scale; Gas Town may be too complex.

### 6. Practical configuration in Android/Termux environment

**Assumptions**:
- Termux + Git + Python/Go environment
- Markdown editing with Obsidian (Android)
- Google Drive sync (via GAS)

**Proposed directory structure**:
```
~/projects/myproject/
  .git/
  .beans/
    inbox/
    active/
    archive/
  .github/
    workflows/
      weekly-sync.yml
  agents/
    CLAUDE.md
  docs/
    weekly-reports/
      2025-W05.md
  README.md
```

**Workflow**:
1. Work at a cafe → start Termux
2. Check the task with `beans tui`
3. Instruct Claude → beans are automatically updated
4. Git commit/push
5. After returning home → Review editing with Obsidian (Android)
6. Sunday night → Weekly script execution → GitHub sync
