# xp_issueArchiveFinalize Functional Specification

## Overview

`<EpicName>/docs/issues/issue-*.MD` (Issue Markdown snapshot generated by `xp_issue2md`) is
By simply saving the GitHub issue state at the time of acquisition, even if the issue is closed on GitHub later, the Markdown side
front matter `state` is not automatically updated.

`xp_issueArchiveFinalize` targets only `state: open` Issue Markdown under the target Epic.
Reconfirm the actual status on GitHub, and if it is closed, replace it with the latest version (Issue #2971 / #3484).

- **Open**: Working cache. Allow some stale
- **After closed**: Completed document. Re-fetch from GitHub and finalize near Epic completion

Constant synchronization and re-enumeration of all issues will not be performed. Only local candidates for `state: open` are queried by the GitHub API.

## Command

```
/xp_issueArchiveFinalize <EpicName>
```

Called by: `xp_Director` (AllGREEN flow step 8. Incorporated in #3485), `daily-tasks` (Section 5.5, Periodic execution of Epic traversal. Incorporated in #3486).

## Processing flow

1. **Candidate extraction** (deterministic/file system only)
   `SoloXP/scripts/find-stale-issue-archives.sh <EpicName>` becomes `<EpicName>/docs/issues/issue-*.MD`
   Scans and outputs the issue number of the front matter `state: open` file as standard output, one per line.
   If `docs/issues` does not exist/there are 0 candidates, return empty (no error).
2. **Reconfirm status** (GitHub API/LLM driven)
   Lightly check the status of each candidate using `gh issue view <n> --json state -q .state`.
   If `gh` cannot be used, fallback to `mcp__github__issue_read` (method: `get`)
   (Identical to the pattern already established in `xp_issue2md`).
3. **finalize or no-op**
   - Candidate found to be `closed`: Calls the existing `xp_issue2md <n>` as is, adding text, comments,
     Regenerate the entire front matter (including `state: closed`). It does not have any new generation logic.
   - Still a candidate for `open`: Do nothing (no unnecessary rewrites).
4. **Summary report**
   Reports the number of scanned items, number of finalized items, and number of skipped items to the caller.

## Executable script

| File | Responsibilities |
|---|---|
| `SoloXP/scripts/find-stale-issue-archives.sh` | Responsible only for the deterministic process of extracting issue numbers of `state: open` candidates from `<EpicDir>/docs/issues/issue-*.MD`. No inquiries to GitHub API |

## Skill itself

| File | Responsibilities |
|---|---|
| `SoloXP/skills/xp_issueArchiveFinalize/SKILL.md` | Call candidate extraction script, reconfirm GitHub status (gh/MCP fallback), `xp_issue2md` finalize and summary report by reuse |

## Non-purpose (Issue #2971)

- We will not create a constant synchronization mechanism that synchronizes Markdown every time an issue comment is added.
- Do not re-enumerate all GitHub Issues with API each time- Fixed Issue Markdown's `state` to SoloXP's `depends_on` and did not make it the SSOT for `[Auditor GREEN]` judgment.
  (Workflow judgment will continue to follow the actual state and existing completion markers on GitHub)
