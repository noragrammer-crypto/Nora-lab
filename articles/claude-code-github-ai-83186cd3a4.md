## AI小説書きあるある：フォワード問題との戦い

AI使って小説書いてる人なら誰でも経験あると思うんだが、「最初から読んでいくと何か変」っていう現象、ありませんか？

途中で書き足したシーンは良い感じなのに、全体を通して読むと「あれ、この設定いつの間に変わってた？」とか「このキャラ、前は魔法使えなかったはずでは…？」みたいなやつ。

私はこれを勝手に**フォワード問題**って呼んでいる。

章単位で見ると完璧なのに、第1章から順番に読むと違和感がある。AIと対話しながら書いていると、どうしてもコンテキストが分断されるから起きるんですね。

## なぜAI小説は設定がブレるのか

理由は単純で、AIは「今見えている範囲」でしか判断できないから。

Claudeと会話しながら第5章を書いてるとき、第1章で設定した細かい制約なんて忘れている。Claudeも覚えていない。結果、矛盾が生まれる。

人間だけで書いてるときも起きることだが、AI協働だと特に起きやすい。なぜなら：

- 執筆スピードが速いから細部の確認が追いつかない
- AIの提案を採用する際、全体整合性まで気が回らない
- 会話が長くなるとコンテキストがどんどん抜け落ちる

## AI編集者という発想

で、ここで思ったわけです。

「最初から通しで読んでチェックする人が欲しい」と。

でもそれ、人間に頼むの大変じゃないですか？　小説全体を最初から読んで、設定の矛盾を指摘してくれる編集者なんて、プロに頼んだらお金かかるし。

そこで気づいた。**Claude Codeに任せればいいんじゃないか。**

## GitHub連携というめんどくさい壁

Claude Codeは、GitHubと連携させることでプロジェクト全体にアクセスできる。つまり、小説の全章全シーンを「読める」状態になる。

ただし、ここには一つハードルがある。

**GitHubの設定、めんどくさい。**

リポジトリ作って、認証して、クローンして…技術者じゃない人には結構きつい。私も最初「うっ」となった。

でもこれ、**一度やってしまえば終わり**なんですよ。

そして一度設定すれば、継続的に「AI編集者」として働いてくれる。私の言う「デジタル農家」的発想ですね。最初に畑を耕す労力はかかるが、その後はずっと収穫できる。

## 実際の使い方：レビュー→修正案→判断

GitHub連携したClaude Codeに、こう頼む。

「第1章から順番に読んで、後の展開と矛盾する記述や、読者が混乱しそうな表現を指摘してください」

すると、Claude Codeは：
1. 全体を読み込んで矛盾を検出
2. 具体的な問題箇所を指摘
3. **修正案をGitのブランチとして提案**

ここがポイント。Claude Codeは修正案を「提案」として投げてくる。

あとは私が：
- 良さそう → **マージ**
- うーん微妙 → **リジェクト**または手動修正

って判断すればいい。

AIが勝手に本文を書き換えるんじゃなく、「こうしたらどうか？」と提案してくれる。最終判断は人間。これが絶妙にいい距離感なんです。

## 誤字脱字から設定矛盾まで

このアプローチの良いところは、チェック範囲が広いこと。

- 誤字脱字（基本）
- 表記ゆれ（「魔法」と「魔術」が混在、など）
- 設定矛盾（キャラの能力、世界観のルール）
- **突然出てくる変な設定**（AI小説あるある）
- フォワード問題全般

全部まとめて見てくれる。

しかもMETAファイルやREADMEに世界観や重要設定をまとめておけば、それを参照しながらレビューしてくれるから精度も上がる。

## 継続的品質管理という考え方

一番気に入ってるのは、**継続的にチェックできる**こと。

新しい章を書いたら、またレビューしてもらう。前の章との整合性もチェックしてもらう。

まるで専属の編集者を雇ってるみたいなものだ。

Gitで管理してるから、「このときの判断は正しかったかな？」と後から履歴も見られる。変更を巻き戻すこともできる。

## めんどくさいを超えた先に

GitHub設定、確かにめんどくさい。

でも一度やってしまえば、その後の執筆が**めちゃくちゃ楽になる**。

AI小説の「スピードは出るけど品質が心配」という弱点を、ちゃんと補える。

私の「働かずに小説を書く」哲学にもぴったり。最初に仕組みを作ってしまえば、あとはAIが働いてくれる。
